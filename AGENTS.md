# AutoMetalSheet Agent Context

## Project Focus

AutoMetalSheet is evolving from midsurface UDF reconstruction toward CAE-ready sheet-metal shell mesh generation.

Current MVP direction:
- Input: canonical filled midsurface STEP files from `C:\Users\hide2\IdeaBox\fill_volume\fill_mid_surf\<assembly>\fill\`.
- Optional conditions: `annotations/joints.json`, thickness/material metadata, load/support metadata.
- Output: analysis-ready midsurface shell mesh, not B-Rep/CAD feature generation.
- Preferred mesh: quad-dominant shell mesh with node/element sets for fasteners, mounts, loads, contacts, boundaries, and refinement regions.
- Filled midsurfaces remain canonical. Fasteners are represented by virtual washer patches by default; reopened hole patches are optional when hole-edge stresses are in scope.
- First MVP success criterion is a deterministic baseline that passes data contracts, set contracts, quality gates, and solver smoke tests. ML starts as a sizing/refinement/protected-region helper, not as the full mesh generator.
- Current near-term generative target: generate midsurface point clouds from constraint points only. The current anchored-scaffold AE is still a midsurface-input reconstruction probe, so it proves scaffold anchoring helps reconstruction generalization, not constraint-only generation. Next architecture work should turn constraint points + metadata into scaffold/anchor priors before local point or mesh generation.

Key design:
- Hierarchical midsurface mesh encoder.
- Coarse global graph path for whole-part structure.
- Fine patch path for boundaries, holes, fasteners, high curvature, and local CAE mesh detail.
- Latent cross-attention fusion.
- Coarse scaffold + adaptive local refinement decoder.
- Deterministic quality projection before export.

## Engineering Guardrails

- Do not treat visual mesh similarity as success. CAE hard gates and mesh quality metrics are primary.
- Do not generate B-Rep directly for the MVP.
- Do not rely on single-part or single-assembly results as evidence of generation generalization.
- The current autoencoder prototype is a structure-understanding probe, not the final CAE mesh generator. It includes a fixed-query unordered point-cloud baseline and a structured scaffold + local refinement decoder.
- The autoencoder defaults to shape-only input. `joints.json` nearest-distance features are opt-in via `--use-joint-distance`.
- Shape-only single-part overfit reached Chamfer about 0.079 on normalized fixed-sample point clouds. Treat this as evidence that the pathway learns, not as evidence of generalization.
- Avoid selecting only the very smallest parts for AE checks; they may be too simple. Prefer bbox-diagonal size quantile 0.2-0.4, using `--size-quantile-min 0.2 --size-quantile-max 0.4`.
- Use `python -m cae_mesh_generator.evaluate_autoencoder --checkpoint <best.pt>` to generate visual target/reconstruction comparisons. Inspect both `recon->target` error and `target->recon` miss coverage.
- q20-40 holdout stable v2: 7 train / 2 val parts gave train Chamfer mean about 12.1mm and val Chamfer mean about 42.1mm. Same-capacity train-all improved the held-out parts when they were included, but aggregate target-within-5mm stayed only about 15.6%. Treat fixed-query point-cloud decoding as a diagnostic baseline, not the path to CAE-ready generation.
- q20-40 structured scaffold holdout v1: 7 train / 2 val parts gave train Chamfer mean about 10.6mm and val Chamfer mean about 30.7mm; val target-within-5mm improved from 4.7% to 13.3% versus the fixed-query baseline. Treat this as evidence for the decoder direction, not as CAE readiness.
- For larger/longer AE training, use validation-aware checkpointing. `train_autoencoder.py --best-metric auto` selects `val_loss` when a validation split exists, and `--eval-every` controls validation cadence.
- Long AE runs support `--save-every` for `last.pt` and `--resume <last.pt>` for restart. For 1000-epoch GPU runs, prefer `--device cuda --epochs 1000 --eval-every 10 --save-every 25`.
