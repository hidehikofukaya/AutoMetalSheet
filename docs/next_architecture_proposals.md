# v2 が失敗した場合の次期アーキテクチャ提案

Date: 2026-08-27
Author: fable5
前提: curve-major AR v2(相対座標+ソフトCE+エッジ数自己条件)が Kaggle 150ep で
「大域一貫性のある生成」に届かなかった場合の選択肢。判定前に読む必要はない。

## 0. まず「v2 の失敗」が何を意味するかを固定する

3世代の失敗の系譜が指す構造的問題は一貫している:

| 世代 | 失敗 | 学んだこと |
|---|---|---|
| 点群 flow | ぼやけ(床12.7倍) | 表現が構造を持たないと駄目 |
| 頂点AR | 点の霧 | 系列順序が幾何の連続性と一致しないと駄目 |
| curve v1/v2 | 徘徊・止まらない | **局所継続は学べる。大域計画が系列のどこにも無い** |

教師強制は常に良い(文法83-100%、粗桁1-2bin)。つまり**左から右への逐次分解そのものが、
「部品全体のレイアウトを先に決めてから細部を埋める」という設計の認知構造と食い違っている**。
v2 の3処方は複利誤差の緩和策であり、この分解自体は変えていない。v2 が失敗するなら、
それは「AR の逐次分解に大域計画の置き場がない」ことの最終確認になる。

対して確実に成立している事実(資産):
- **大域は低次元なら学べる**: twopoint flow(1M params)は条件→大域パラメータ分布を学び検索に勝った
- **局所は学べる**: v2 の traversal 順で「前のワイヤーから次を伸ばす」は成立(ptr 86%)
- 欠けているのは両者を繋ぐ**学習された大域計画**だけ

## 案A(本命): 階層生成 — 学習された「計画トークン」を先に出す

```text
Stage 1: VQ-VAE  ワイヤーフレーム → 離散コード列 z(16〜64トークン) → 復元
Stage 2: 条件付き prior  (締結点+包絡) → z を生成(AR または離散diffusion)
Stage 3: 詳細デコーダ  z を条件に curve-major AR(v2そのまま)がワイヤーを生成
```

- **思想**: ユーザーが以前提案した「構造形状/詳細形状の分離」を、手設計の θ ではなく
  **学習された離散語彙**として実装する。z は「このパネル構成・この motif 配置」を表す
  ニューラル DSL になり、族が増えても語彙が育つ(twopoint θ の族ロックイン問題を回避)
- なぜ効くか: (1) 大域一貫性は 16-64 トークンの短い系列の問題になる(複利誤差が
  ほぼ消える)。(2) 詳細 AR は z に強く条件付けられ「どこで止まるか」を z が教える
  (エッジ数自己条件の一般化)。(3) Stage 3 は v2 の資産をほぼ流用
- 先例: VQ 系2段生成(DALL-E 1 / VQ-GAN 系)、CAD では SkexGen のコードブック分離
- リスク: VQ の学習安定性(コード崩壊)。対策は既知(EMA、コードリセット)
- 工数: 中。Stage 1 が新規、Stage 2 は twopoint flow の骨格流用、Stage 3 は既存

## 案B(対抗): 非AR — グラフ反復精緻化(discrete + continuous diffusion)

```text
エッジ集合を一括保持: 各要素 = (型, 端点座標×2, 存在フラグ)
diffusion/flow: 全要素を並列にノイズ除去(graph transformer、T=20-50反復)
端点共有は decode 時の溶接(定義6のマージ規約)+共有を促す補助損失
```

- **思想**: exposure bias を緩和でなく**構造的に消す**。反復精緻化は毎ステップ
  「完成形の下書き全体」を見て修正するため、複利する誤差経路が存在しない。
  エッジ数は存在フラグの和として自然に決まる(STOP 問題も消える)
- 先例が強い: **HouseDiffusion**(間取り=型付き線分ループ+接続制約のベクトル生成)は
  本タスクとほぼ同型の問題を diffusion で解いた。DiGress(離散グラフ diffusion)、
  PolyDiffuse。我々自身の twopoint flow の成功も「連続量は flow が得意」の傍証
- 理論との関係: final_wireframe_theory は F2(祖先サンプリングの厳密性)で AR を採用したが、
  同文書は「実装からのフィードバックによる改訂」を明示的に許容している。厳密サンプリング
  より大域一貫性が支配的であることが3世代で示されたなら、F2 は落とすべき保証である
- リスク: 可変要素数(パディング+存在フラグで対処)、端点共有の学習
- 工数: 中〜大。ただし表現・データ・評価(wtok/評価3分解)は全て流用可能

## 案C(安価・即効): v2 を保ったまま「探索と自己修正」を足す

v2 の診断が「教師強制は良い、rollout だけ悪い」である以上、生成時に探索を足すだけで
かなり回収できる可能性がある:

1. **検証器付きビーム/best-of-N**: 部分ワイヤーフレームを採点する小さな critic
   (GT=正例、モデルの暴走 rollout=負例で学習)でビームを刈る。負例はいくらでも
   自家生成できるので学習が容易
2. **自己修正学習(scheduled sampling / DAgger 型)**: モデル自身の rollout を接頭辞に
   して GT 継続を教師にする微調整。exposure bias への古典的直接処方
3. **系列レベル微調整**: rollout の Chamfer を報酬に方策勾配で仕上げ(少量)

- 工数: 小(1週間以内)。**v2 が「惜しい」失敗だった場合の第一手**
- 上限: 分解自体は変わらないので、大域計画の欠如が本因なら頭打ちする

## 推奨する意思決定

```text
v2 評価で edge_ratio が 1 に近づき Chamfer だけ残る  → C(探索+自己修正)で仕上げ
v2 でも徘徊・止まらないが継続は綺麗              → A(階層計画)。Cを併走可
v2 で局所品質も伸び悩む                        → B(グラフdiffusion)へ転換
```

A と B は排他ではない: Stage 2 の prior を diffusion にすれば A は B の利点(並列・
非逐次)を計画レベルで取り込める。**最終形は「diffusion で計画、AR で詳細」の
ハイブリッド**になる可能性が高い、というのが私の予想。

## 共通して保存される投資

wtok 表現(忠実度0.55mm)・変換パイプライン・トラバース順・評価プロトコル
(誤差3分解・レンダリング・val固定)・Kaggle 基盤は**全案でそのまま使う**。
捨てる可能性があるのは「左→右の1段 AR」という分解だけである。
