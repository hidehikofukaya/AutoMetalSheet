## 0. エグゼクティブサマリ

anchored scaffold の設計判断は正しく、P0修正(評価較正・epoch毎再サンプリング)の実装と軸アブレーションの実施も適切だった。ただし **val Chamfer 6.317mm という数字は額面通りに読んではいけない**。アンカーが入力点群そのものから選ばれているため(オラクルリーク)、再構成タスクの大部分が「学習された理解」ではなく「入力ジオメトリの直通コピー」で解かれている。

それでも本物の成果が2つある:

1. 「表面近傍に足場を置き bounded residual で仕上げる」構造の有効性が証明された(アーキテクチャの証明)
2. **local refinement decoder は資産として完成に近い** — 正しい足場さえ与えれば板金らしい表面を張れる

問題は「足場をどう置くか」に完全に還元された。次の勝負は「入力なしで足場を置く」ことであり、その橋が **アンカー疎化カリキュラム** と **scaffold 蒸留** である。

## 1. ローカル検証と 6.317mm の解釈

### 1.1 検証した事実

- `runs/..._anchored_seed13_eval_all24_best_calibrated4096/aggregate_metrics.json`: train 5.639mm / val 6.317mm / target within 5mm 0.604 vs 0.548 — レポートと一致
- `hierarchical_ae.py` の `select_scaffold_anchors`: アンカーは `memory["coarse_centers"]` / `memory["fine_centers"]` から選択。これらは **encoder が入力点群から計算した、入力中立面上の点** である
- residual は tanh で ±0.08(正規化空間)に制限 → 250mm級パーツで最大約20mm

### 1.2 オラクルリークの構造

scaffold = clamp(入力表面上の点 + 小さな residual) であるため、**scaffold が中立面に乗るのは学習の成果ではなく構造上の保証**。証拠は3つ:

1. **train/val ギャップのほぼ消滅**(Chamfer/floor 2.68x vs 2.73x)。真の汎化改善というより、入力→出力のショートカットが生まれてタスク自体が易化したときの典型的シグネチャ
2. **scaffold within 5mm = 1.000/0.999** — アンカーが入力点なのだからトートロジーに近い。scaffold 診断はもはや「配置能力」を測っていない
3. 拘束点のみ生成ではこのショートカットが存在しない(§5.2 で codex 自身が認識している通り)

### 1.3 それでも得られた本物の成果

- learned scaffold の val scaffold p95 70.5mm → 表面近傍アンカーで 2.5mm。**「足場が表面近傍にあれば勝てる」ことの決定的な実証**
- 081 の recon p95 2.615mm、boundary p95 7.063mm — refinement decoder は正しい足場の上でなら CAE 品質に近い表面を張れる。**この decoder は次段階で凍結レンダラーとして再利用すべき資産**

## 2. §7 の質問への回答

### Q1. anchored 結果は拘束点生成への帰納バイアスの証拠としてどう評価するか

「表面近傍足場 + bounded residual という構造が正しい」証拠としては強い。「モデルが表面位置を**推論**できる」証拠としてはゼロ(推論せず入力からコピーしている)。拘束点生成に必要なのは後者。次の実験はこのギャップを直接測るべき(Q2 のアンカー疎化)。

### Q2. 中立面入力なしでアンカー候補を何から作るか

一足飛びに答えを決めず、**アンカー疎化カリキュラム**で橋を架けることを推奨する:

- 学習時にアンカー予算をランダムに間引く: 全 centers → 64点 → 16点 → 拘束点相当の 4〜8点
- アンカー数 vs val 品質の曲線を測る。これは「アンカーに載っている情報 vs latent に載っている情報」の分解測定であり、同時に拘束点のみ生成への**連続的な訓練経路そのもの**
- 曲線が緩やかに劣化 → latent が実仕事をしている。急崖 → 現在の latent はショートカット依存で育った空の器であり、scaffold prior generator を本格的に作る必要がある

その先の本命は **scaffold 集合の条件付き生成モデル**:

```text
拘束点 + メタデータ
  -> constraint encoder
  -> conditional diffusion / flow matching
  -> scaffold 集合 (64〜256点)
  -> 凍結 refinement decoder
  -> 点群 / mesh IR
```

scaffold は低次元なので生成が安く、多様性(§6.3)も diffusion が自然に扱う。難しい生成問題を「小さな点集合の生成」に切り詰めるのが、今回の結果の正しい活かし方である。

### Q3. 拘束点のみは不良設定か、必須メタデータは何か

決定的写像としては不良設定、**条件付き生成としては成立する**。幾何を決める最低限のセット:

1. 拘束点 + タイプ(締結 / 取付 / 支持)
2. **design envelope(bbox)** — これがないとフランジの伸びが非有界
3. 板厚
4. 対称フラグ

material / load は CAE 的に重要だが幾何生成の第一段では不要(phase 2)。

ただし率直に言えば、**最大の不良設定要因はメタデータ不足ではなくデータ量**。2アセンブリ・24(最大65)パーツで条件付き生成モデルを訓練すれば、ほぼ確実に記憶=検索になる。Q7 の検索ベースラインを必ず併走させること。

### Q4. 点群直接生成か、scaffold / boundary chain / mesh IR 先行か

**scaffold 先行**。今回の実験アークの教訓そのもの — 拘束点から点群を直接生成するのは、free learned query の失敗を生成スケールで再演することになる。

順序: 拘束点 → scaffold nodes → boundary chains → refinement / 密度 → mesh IR。boundary chain を2番目に置くのは、CAE 要件でありかつ boundary 教師データが既に整備済みだから。

### Q5. 現在の AE checkpoint から教師信号を作れるか

作れる。2通りあり、両方とも今すぐ使える:

1. **scaffold 蒸留**: anchored AE を全パーツに走らせ、scaffold 集合(+ refinement logits)を保存。これが「拘束点 → scaffold」生成モデルの ground truth になる。AE は教師、refinement decoder は凍結レンダラー
2. **latent 回帰**: 拘束点 encoder に AE の latent を予測させ、凍結デコーダで復元。**ただし先にアンカー摂動テストをすべき** — latent を保持したままアンカーだけをノイズ化/疎化して復元品質の劣化を測る。ショートカット依存で育った latent は空の可能性があり、その場合この経路は死んでいる。学習ゼロ・スクリプト1本で判定可能

### Q6. 多様性を保ちつつ板金らしい形状制約を入れる構造

3層に分離するのが定石:

| 層 | 担当 | 実装 |
|---|---|---|
| 多様性 | scaffold 生成コア | conditional diffusion / flow matching |
| 拘束充足 | ハード処理 | 拘束点近傍の scaffold を拘束点にスナップする射影(厳密保証) |
| 製造制約 | 後段フィルタ | 最小曲げR・板厚整合をサンプルのフィルタ / ランキングで |

製造制約を生成コアの prior に焼き込むと多様性が死ぬ。データが少ない今は特に致命的なので、まずフィルタで運用する。

### Q7. 点群生成段階で必須の評価指標

1. **拘束充足距離**(各拘束点 → 生成表面の距離の max / mean)— これが契約。最優先
2. 較正済み Chamfer 系(ホールドアウトパーツの拘束点で条件付けし、実パーツ表面と比較)
3. **train-NN 検索ベースライン**: 各 val 拘束点配置に対し「拘束配置が最も近い訓練パーツをそのまま返す」場合の Chamfer を併記。**生成モデルはこれに勝てて初めて生成と呼べる**。現在のデータ規模では最重要の誠実性指標
4. 同一拘束条件下のサンプル間 pairwise Chamfer(多様性)
5. solver import smoke は mesh IR 段階まで不要

## 3. 推奨実行順

1. **アンカー摂動・疎化診断**(学習ゼロ、既存 checkpoint)— latent が空か実仕事をしているかを判定。以降の全分岐を決める
2. **アンカー疎化カリキュラムで AE 再訓練**(全 → 64 → 16 → 8点)— 拘束点生成への連続的な橋
3. **scaffold 蒸留データセット作成**(Q5-1)+ 拘束点データ整備(joints.json 由来の締結点)
4. **データ拡大**(65候補全部 + 未処理3アセンブリの mid/fill 抽出)— 生成フェーズは AE フェーズ以上にデータ律速
5. 拘束点 + envelope → scaffold の条件付き生成モデル(diffusion / flow、検索ベースライン併走)
6. 凍結 refinement decoder を接続して end-to-end 評価

## 4. 一文要約

anchored scaffold は「足場を表面近傍に置けば勝てる」ことを証明したが、6.317mm は入力→アンカーのショートカットで易化した数字であり、次の勝負は「入力なしで足場を置く」こと — その橋がアンカー疎化カリキュラムと scaffold 蒸留である。
