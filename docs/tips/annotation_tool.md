# ジョイントアノテーションツール 設計ドキュメント v0.2

記録日: 2026-06-23
状態: 主要設計判断は確定（§8参照）。残るのは実装時に詰める具体値のみ。

---

## 1. 目的

板金BIWアセンブリのSTEPデータから、

1. 部品同士の締結点（溶接打点／ボルト締結点／その他取付穴）を、複数部品にまたがる「ジョイント」として正確にアノテーションする
2. アノテーション後、各部品の穴をすべて埋めて中立面生成・AI学習用データを作る（穴埋め自体は別アプリ、本ツールはアノテーションのみを担当）

を実現する、新規スクラッチ実装のインタラクティブツール。

過去プロジェクト（`_archive_pre_annotation_tool/`）は目的・目標の参考情報としてのみ保持し、コードベースとしては引き継がない。ただし `stp_viewer.py` / `annotator.py` / `hole_filler.py` は実装パターンの参考として読み解きながら使う（詳細は §4, §6.4）。

## 2. スコープ

- 対象: `C:\Users\hide2\IdeaBox\Mesh_Generater\output\<assembly_id>\` 形式のディレクトリ全般（`A0072601285` はその一例であり、今後増える他アセンブリにも同じツールで対応できるよう汎用設計とする）
- 本ツールの責務: **アノテーション（ジョイント・取付穴の記録）のみ**。STEPの穴埋め自体は別アプリ（既存 `hole_filler.py` 相当、将来作り直す可能性あり）に委譲する。本ツールは穴埋めツールへの入力契約（§7）を満たす出力を生成する。
- 非対象（本フェーズ）: パラメトリックCAD復元、AI学習パイプライン本体、CATIA連携。

## 5. データスキーマ（確定、v1.1）

過去PCセッションで提案された joint-graph スキーマ（`parts` + `joints`、`per_part` に各部品ごとの局所情報を持つ）をベースに拡張する。

```json
{
  "schema_version": "1.0",
  "source": {
    "assembly_dir": "C:/Users/hide2/IdeaBox/Mesh_Generater/output/A0072601285",
    "hierarchy_json_mtime": "...",
    "full_assembly_stp": "full_assembly.stp"
  },
  "parts": [
    {
      "part_id": "body002",
      "stp_file": "bodies/body002.stp",
      "vtp_file": "bodies/body002.vtp",
      "tag": "sheet_metal",
      "thickness_mm": 1.682,
      "thickness_source": "hierarchy_est"
    }
  ],
  "joints": [
    {
      "joint_id": "j0001",
      "type": "bolt",
      "parts": ["body002", "body014"],
      "axis": {
        "start_xyz": [2613.4, 552.3, 326.9],
        "direction_xyz": [0.0, 0.0, 1.0],
        "length_mm": 4.6,
        "direction_user_selected": true
      },
      "per_part": [
        {"part_id": "body002", "hole_center_xyz": [...], "hole_diameter_mm": 12.0, "detection_method": "auto_hardware"},
        {"part_id": "body014", "hole_center_xyz": [...], "hole_diameter_mm": 12.1, "detection_method": "auto_circle"}
      ],
      "source_hardware_part_id": "body017",
      "confidence": "auto_suggested",
      "created_by": "user",
      "created_at": "2026-06-23T..."
    },
    {
      "joint_id": "j0002",
      "type": "weld",
      "parts": ["body002", "body005"],
      "axis": {
        "start_xyz": [2601.1, 548.9, 327.4],
        "direction_xyz": [0.0, 0.0, 1.0],
        "length_mm": 3.09,
        "direction_user_selected": true
      },
      "per_part": [
        {"part_id": "body002", "contact_xyz": [...], "local_thickness_mm": 1.682, "detection_method": "manual"},
        {"part_id": "body005", "contact_xyz": [...], "local_thickness_mm": 1.41, "detection_method": "manual"}
      ],
      "confidence": "user_confirmed"
    },
    {
      "joint_id": "j0003",
      "type": "mounting_hole",
      "parts": ["body008"],
      "axis": {"start_xyz": [...], "direction_xyz": [...], "length_mm": 1.6, "direction_user_selected": true},
      "per_part": [{"part_id": "body008", "hole_center_xyz": [...], "hole_diameter_mm": 8.0, "detection_method": "manual"}],
      "confidence": "manual"
    }
  ]
}
```

設計判断:

- **`joints[].parts` は N≥1 を許容**する統一スキーマとする。`weld`/`bolt` は通常 N≥2、`mounting_hole` は単一部品（N=1）も自然に表現できる。これにより「その他取付穴は単一部品しかありえないか」という疑問にもスキーマレベルで答えが出る（単一でも複数でも同じ構造で表せる）。
- **`axis`（締結軸線）は `bolt` / `mounting_hole` / `weld` の全タイプに統一適用する**（ユーザー確認済み：「溶接も軸線化する」）。板厚方向に伸びる軸線として、自動検出（穴の円フィット法線、または接触面の法線）から初期値を立て、ユーザーは「反転」ボタンで `direction_xyz` の向きだけを切り替えられるようにする（始点・終点の再ピックは不要）。これにより3タイプとも同一のギズモ描画・編集UIで扱える（§6.6の可視化・編集ロジックが型分岐不要になる）。
  - `bolt`/`mounting_hole`: `axis.length_mm` は穴が貫通する板厚（またはハードウェアの軸長）。
  - `weld`: `axis.length_mm` は打点を構成する各部品の `local_thickness_mm` の合計（スタック厚）。`per_part[].contact_xyz` が各部品側での軸線との交点（旧 `mid_xyz` 相当）。
  - 3タイプとも `per_part` 配列の要素数は `parts` 配列と1:1対応する。フィールド名は意味に応じて使い分ける（`hole_center_xyz`+`hole_diameter_mm` は穴系、`contact_xyz` は溶接系）が、`axis` オブジェクト自体の構造は完全に共通。
- `confidence` フィールドは `auto_suggested`(金具/穴検出からの自動提案、未確認) / `user_confirmed`(自動提案をユーザーが確認・採用) / `manual`(完全手動) の3値とし、後から「自動提案のうち未確認のものだけ再レビュー」のようなフィルタができるようにする。

## 6. UX設計

### 6.1 フォーカス部品選択

`stp_viewer.py` のパーツツリー（`hierarchy.json` 駆動、フィルタ機能付き）を踏襲。`tag` でのフィルタ（`sheet_metal` のみ表示等）に加え、アノテーション進捗（ジョイント0件／一部／レビュー待ちあり）のインジケータを追加する。

### 6.2 3段階透明度・隣接判定（確定: 面間ギャップ距離方式）

旧 `stp_viewer.py` はCATIA階層上の「兄弟/親子」関係で透明度を決めていたが、これは物理的な隣接性と一致しない（同じサブアセンブリでも離れた部品、別サブアセンブリでも密着した部品があり得る）。今回は**幾何学的な面間ギャップ距離**に置き換える。

アルゴリズム（高速化のため2段階）:
1. フォーカス部品のbboxを閾値分だけ拡張し、交差するbboxを持つ部品のみを候補に絞り込む（軽量フィルタ）。
2. 候補に対してのみ `.vtp` メッシュ同士の最近接距離（点群kd-treeで近似、または面メッシュ間の最近接距離）を計算する。
   - 距離 ≤ `adjacency_gap_threshold_mm` → 隣接（半透明表示）
   - それ以外 → 非隣接（透明/極薄半透明）
   - フォーカス部品自身は常に不透明。

**[要確認] `adjacency_gap_threshold_mm` の初期値**: 提案は **15mm**（BIWのフランジ重ね代・組付け公差を考慮した目安値）。実装後、`A0072601285` の実データで実際に隣接表示される部品数を可視化しながら調整する想定です。妥当そうであればこのまま進めます。

### 6.3 接触面ハイライト

フォーカス部品と隣接部品それぞれについて、6.2のメッシュ間最近接距離計算で「閾値内に入った面・頂点」を記録しておき、その領域を別色でオーバーレイ表示する。これにより「どこが接触面か」をユーザーが一目で確認しながら打点できる。

### 6.4 ボルト穴自動検出・金具活用（確定: 金具活用する）

二段構えで候補を生成する:

1. **金具ベースの自動提案（新規）**: `tag="small_hardware"` の部品について、その重心・主軸（PCA等で円柱軸を推定）を計算し、軸方向に沿って交差する `sheet_metal` 部品を探索 → 軸・関与部品の組をジョイント候補として自動生成する。ユーザーは候補リストから確認・採用するだけで済む（穴を1つずつ手動で探す手間を削減）。
2. **円形穴の解析的検出（既存 `hole_filler.py::detect_holes()` を踏襲・緩和）**: 金具が存在しない/単独の穴については、B-Repの円筒面・円形エッジから穴候補を検出する既存ロジックを土台に、**検出漏れを減らす方向（再現率優先）でパラメータを緩める**。
   **[要確認]** 旧ロジックは直径で `JIG_DIAM_MM=5.0`(無条件で埋める)/`BOLT_DIAM_MM=15.0`(埋めて記録)を分けていましたが、これは「穴埋め時の自動判定」用途の閾値であり、本ツールの「候補として拾うかどうか」の閾値とは目的が異なります。実装時に `detect_holes()` の中身（円形度判定の許容誤差など）を確認した上で、直径レンジを広げる・円形度の許容誤差を緩める、の両面から再現率優先のデフォルト値を提案します。

### 6.5 部品間穴マッチング（確定: 数mm許容）

フォーカス部品で穴（または金具軸）を選択した後、隣接部品側の対応する穴を探す際は、**完全一致ではなく許容誤差つきの近傍探索**を行う。

**[要確認] 既定許容値の提案: 5mm**（ご指摘の「数mmずれる可能性がある」を踏まえた初期値）。軸方向にも垂直方向にも、穴中心同士の距離がこの範囲内であれば候補として提示する。

### 6.6 フォーカス切替時のアノテーション可視性（確定: 必須要件として設計に組み込み）

`joints[].parts` に現在フォーカス中の `part_id` が含まれる全ジョイントを、フォーカス対象に関わらず常時インデックス参照できるよう、`part_id → joint_id[]` の逆引きインデックスをメモリ上に保持する（アノテーションデータ自体は引き続き `joints` 配列がsingle source of truth）。フォーカス切替のたびにこのインデックスを引いて、関連ジョイントのギズモ（軸線）を3Dビューに描画し、クリックで編集可能にする。§5確定により `weld`/`bolt`/`mounting_hole` の3タイプとも `axis` 構造が共通なので、ギズモ描画・編集ロジックは型ごとの分岐なしに実装できる。

## 7. 入出力契約（穴埋めツールとの境界）

- 本ツールの出力: `joints.json`（§5のスキーマ）+ 各 `sheet_metal` 部品について検出済み・未アノテーションの穴一覧（穴埋めツール側が「ジョイントに紐づかない穴は埋めてよい」と判断するための情報）。
- **穴埋め方針（確定: 直径によらず全て埋める）**: 旧 `hole_filler.py` の「直径15mm超は保持（埋めない）」という設計を**廃止**する。ジョイントに紐づく穴（ボルト穴・取付穴）はもちろん、アクセス穴・大型カットアウト等の大径穴も含め、**サイズによらず全てのジオメトリ上の穴を埋める**（ユーザー確認済み: 「全て埋める(推奨)」）。位置・サイズ・用途等の意味情報は穴埋めの前にアノテーションデータ側（`joints.json` および検出済み穴一覧）に保持されるため、ジオメトリを完全に埋めても情報は失われない。
- **保存場所（確定: ソースデータ側）**: アノテーション成果物は `Mesh_Generater/output/<assembly_id>/annotations/joints.json`（および付随する未アノテーション穴一覧等）として、**ソースデータと同じ場所**に保存する（ユーザー確認済み: 「Mesh_Generater側(ソースと同位置)(推奨)」）。`AutoMetalSheet` 側のリポジトリには出力データを置かない（ツールのコード・設定のみを置く）。これにより、同じ `assembly_id` のソースデータとアノテーション成果物が常に同じディレクトリツリー内で一緒に移動・バックアップされ、アセンブリが増えても `Mesh_Generater/output/<assembly_id>/annotations/` という同一パターンで管理できる。

## 9. 次のステップ

主要設計判断が確定したため、`AutoMetalSheet/annotation_tool/` 配下にプロジェクト骨格（`src/`, `tests/`, 依存定義）を作成し、まずは「アセンブリ読み込み＋部品ツリー表示＋3段階透明度」という最小機能から実装に着手する。実装の過程で #2〜#4 の暫定値を実データで検証し、必要なら調整する。
