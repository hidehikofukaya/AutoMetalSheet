# C案改: 探索+自己修正の改訂版(v2 実測に基づく)

Date: 2026-08-27
Author: fable5
根拠データ: Kaggle v2 150ep の評価(runs/kaggle_v2_150)+本日のローカル headroom 実測

## 0. v2 の結果が C案の前提をどう変えたか

| v2 で判明した事実 | C案への含意 |
|---|---|
| edge_ratio 4.68→1.19、acc_STOP 0.75 | C案の適用条件「量は合っている」を**初めて満たした** |
| 座標配置が崩壊(外形カバー 52mm)— 原因は粗桁相対/細桁絶対の不整合(Opus診断) | **C は座標修正(v2.1)の上に載せる**。壊れた配置の上で探索しても拾う候補がない |
| rollout 間の分散が巨大(同一部品で 28〜200mm) | **分布は良いモードを含んでいる** → 選別の価値が高い |

## 1. headroom 実測(v2 checkpoint、val 6部品 × 5シード)

| 選び方 | Chamfer 中央値 |
|---|---:|
| 1発サンプル(現行) | 72.1mm |
| 平均(参考) | 102.9mm |
| **オラクル選別**(min-of-5、GT使用=上限) | **61.8mm** |
| **ルール検証器の選別**(GT不使用) | **61.8mm** |

発見:
1. **min-of-5 だけで中央値 -14%、部品によっては半減**(74.5→33.4、71.0→28.7)。N を16〜32に
   増やせばオラクルはさらに下がる
2. **学習ゼロのルール検証器が、6部品中4部品でオラクルと同一の候補を選んだ**(中央値は一致)。
   使った特徴は4つだけ: 締結点カバー距離 / 包絡逸脱率 / ぶら下がり端点率 / 異常長エッジ率。
   ※単独特徴と Chamfer の大域相関は弱い(-0.15)が、**部品内の相対ランキング**(z正規化合成)
   としては機能する — 検証器は「絶対品質の予測」でなく「同条件候補の順位付け」に使うのが正解
3. 上限が 61.8mm 止まりなのは v2 の配置崩壊のため。**v2.1(座標修正)後は
   v1 の配置精度(外形14.5mm)を土台に同じ selection が効く**見込み

## 2. C案改の構成(4層、下から順に実装)

### L0(前提): v2.1 = 座標表現の修正

相対座標を撤回し絶対座標に戻す。**効果が実証された2処方(ソフトターゲットCE、
エッジ数自己条件)は残す**。これは C案の一部ではないが、C の土台として必須。

### L1: サンプリング時の構成的ゲート(学習ゼロ、デコード中の探索)

生成中の各座標サンプルに、**教師データの統計から作った台のマスク**を適用:
- 包絡+マージン外の座標を禁止
- 「直前構造からの跳び」が GT 分布の99.9%点を超える NEW 頂点を禁止
  (v2 レンダリングの「彼方へ伸びる長い線」を構成的に排除 — CIRCLE_C と同じ
  「表現上ずれようがない」思想のサンプリング版)
- エッジ数が bucket 予測の±50%を超えたら STOP 圧を上げる

### L2: ルール検証器 + best-of-N(学習ゼロ、実測済み)

N=16〜32 サンプル → 4特徴の部品内 z 合成でランキング → 最良を採用。
実測でオラクル一致率 4/6・中央値一致。**今日から使える**。
コスト: 推論 N 倍 — KVキャッシュ実装(積み残しの高費用対効果タスク)とセットで導入。

### L3: 学習を伴う2段(L2 で頭打ちしたら)

1. **学習ランカー**: L2 のルール特徴+ワイヤーフレーム埋め込みから「同条件候補の順位」を
   学習(教師 = 自家生成 rollout の実 Chamfer 順位。**負例もラベルも無料**)。
   ルール検証器が外した 2/6 のケースを拾いに行く
2. **ノイズ注入自己修正学習**: 教師強制の入力座標側に「モデルの実測誤差分布」
   (粗桁±1-2中心、まれに大ジャンプ)からサンプルしたノイズを注入し、クリーンな
   GT をターゲットに学習 — 「自分のドリフトから復帰する」能力を直接訓練する。
   scheduled sampling の安価な近似で、dataset builder の変更のみ

### L4(任意): 系列レベル微調整

rollout の Chamfer を報酬に方策勾配で仕上げ。L3 まで効いた場合の最後の絞り込み。

## 4. C改が本質的に賭けているもの

v2 が示した「分散の大きさ」は、モデルの分布が**良い解を既に含んでいる**ことを意味する。
C改は「分布を変える」のではなく「分布から良い解を引き当てて選ぶ」戦略であり、
その成否は分布の中身に依存する。だから L0(座標修正)が全ての前提 — 分布の中身が
壊れていれば、どれだけ上手に選んでも壊れた候補しかない。
