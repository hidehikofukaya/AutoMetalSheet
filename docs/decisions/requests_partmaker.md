# 依頼: ワイヤーフレーム抽出の拡張

宛先: CATIA 側の抽出を担当している Claude
発信: 生成モデル側
Date: 2026-08-30

---

## 要旨

現在の抽出データは**辺のクラスが2種類しかなく**、板金部品の形状を表しきれていません。
測定で、**表面の 7.8%(p90 15.1%)が「曲がっているのに、どの曲げ線からも15mm以上
離れている」**ことを確認しました。生成モデル側はこのデータに合わせて表現を作って
いるため、抽出が拡張されない限り、穴・ビード・変曲を持つ部品は原理的に扱えません。

以下、**測定した事実 → 依頼内容 → 受け入れ条件** の順に書きます。

---

## 1. 現状のデータに何が入っているか(実測)

対象: `runs/wtok_synth` の 2300 部品

```
edge classes : {'outer_boundary': 40354, 'bend_line': 136466}
vertex types : {'FIX', 'END', 'MID'}
edge tau     : {'LINE': 134272, 'ARC': 42451, 'CIRCLE': 97}
```

1部品のデータ構造:

```python
part.vertices = [{'T': 'FIX'|'END'|'MID',
                  'bin': (i, j, k),          # env_lo..env_hi を 2^14 で量子化
                  'nf': [x, y, z] | None},   # FIX のみ軸を持つ
                 ...]
part.edges    = [{'cls': 'outer_boundary'|'bend_line',
                  'tau': 'LINE'|'ARC'|'CIRCLE',
                  'refs': [v0, v1] | [v0, vmid, v1]},
                 ...]
part.env_lo, part.env_hi                     # 量子化のための箱
```

---

## 2. 測定した不足 — 3点

### 2.1 曲げ線がパネルを分けきれていない

| | 中央値 | p90 | 最大 |
|---|---|---|---|
| 表面から検出される平面パネル | **18** | 32 | 40 |
| `bend_line` が印付ける折り(対統合後) | **14** | 19 | 22 |

N枚のパネルを分けるには最低 N-1 本の折りが必要ですが、足りていません。

> 注: パネル数は表面法線を15°で束ねた数なので、曲げ部の円筒面が分裂して過大に
> 数えられている可能性があります。そのため次の測定も行いました。

**表面の 7.8%(p90 15.1%)が、曲率を持ちながら、印付けられた曲げ線から15mm以上
離れています。**これは曲げ円筒の近傍を除外した測定なので、`bend_line` が説明して
いない曲率です。該当しそうなもの:

- 基準面が変曲する境界(曲率の符号が変わる線)
- ビードの曲げ部
- コーナー部の曲げ・逃がし

### 2.2 内側の境界(穴・切り欠き)が1つも無い

600部品すべてで、`outer_boundary` の頂点は**全て次数2、境界ループは1本**でした。

```
outer_boundary vertices with degree != 2 : {0: 400}   # 400部品すべてで0個
loops per part                           : {1: 600}   # 600部品すべてで1ループ
```

穴・窓・切り欠きが**1つも抽出されていない**か、部品側に存在しません。
実部品に穴があるなら、抽出漏れです。

### 2.3 締結点以外の拘束・特徴が無い

`FIX` は1部品ちょうど2点。それ以外の機能的特徴(位置決めピン、他部品との合わせ面、
溶接点など)を表す頂点型がありません。

---

## 3. 依頼内容

### 3.1 【最優先】内側境界の抽出とループの識別

穴・切り欠き・窓の境界を抽出し、**どのループに属するかを辺に持たせてください。**

```python
{'cls': 'outer_boundary', 'loop': 0, 'tau': ..., 'refs': [...]}   # 外周
{'cls': 'inner_boundary', 'loop': 1, 'tau': ..., 'refs': [...]}   # 穴 1
{'cls': 'inner_boundary', 'loop': 2, 'tau': ..., 'refs': [...]}   # 穴 2
```

- `loop` は部品内で一意な整数。**外周を 0** にしてください
- `loop` が付いていれば、辺を並べ替えずに境界を復元できます
- 外周が複数ある部品(分離した島)が存在するなら、それも別 `loop` で

**なぜ最優先か**: 生成モデルの外形表現は**単一の閉ループ**を前提にしています。これが
閉ループ保証・接続の無料化を生んでいる土台ですが、穴のある部品は表現できません。
こちら側で複数ループへの一般化を進めていますが、**ループ識別子が無いと学習できません。**

### 3.2 曲げに関するクラスの分離

現在 `bend_line` に混在しているもの、および欠けているものを分けてください。

| 希望する `cls` | 内容 | 現状 |
|---|---|---|
| `bend_line` | 曲げ円筒と平面の接線(現状のもの) | あり |
| `bead` | ビードの曲げ部 | **無い** |
| `inflection` | 基準面の曲率が変わる境界 | **無い** |
| `corner_relief` | コーナーの逃がし・曲げ | **無い** |

**加えて、可能であれば `bend_line` に「折り」の識別子を。**

現状 `bend_line` は**円筒と平面が接する線**を印付けているため、**1つの折りが2本を
生みます**(二面角0°、間隔 = 曲げ半径ぶんで中央値 5.5mm)。こちら側では平行な対を
幾何的に統合していますが(24本 → 15本)、17.2% が対にならず残ります。

```python
{'cls': 'bend_line', 'fold': 3, 'side': 0, ...}   # 折り3 の片側
{'cls': 'bend_line', 'fold': 3, 'side': 1, ...}   # 折り3 のもう片側
```

`fold` があれば統合が幾何推定でなく確定になります。**さらに `angle`(曲げ角)と
`radius`(曲げ半径)があれば、板金として成立するかの検証に直接使えます。**

### 3.3 短いセグメントの扱い

`bend_line` の **61% が 10mm 未満**で、全長の 11.9% しか持ちません。テッセレーション
の破片と判断して切り捨てています(被覆の損失 0.42mm)。

**これが本当に破片なのか、意味のある短い曲げなのかを確認してください。**
意味があるなら、切り捨てている現状が誤りです。

### 3.4 【任意】締結点以外の拘束点

位置決めピン、合わせ面、溶接点などがあれば、`T` を分けて出してください
(`'T': 'PIN'`, `'T': 'WELD'` など)。

**理由**: 測定の結論として、**器を増やしても情報は増えません**。一括生成器の出力を
外形生成器の条件に入れる実験は2回とも失敗しましたが、原因は「どちらも同じ締結点2点
から生成されているので情報が増えない」ことでした。**精度を上げる唯一の手が、
締結点から導出できない新しい入力を足すこと**です。優先度は 3.1〜3.3 の後で構いません。

---

## 4. 受け入れ条件(こちらで検証します)

| # | 条件 |
|---|---|
| A | `loop` を使って境界を復元すると、各ループが閉じている(端点が残らない) |
| B | 穴を持つ部品で `inner_boundary` が実際に出ている |
| C | 新クラスを含めて曲げ線を辿ったとき、**「曲がっているのに曲げ線から15mm以上離れた表面」が 7.8% から有意に下がる** |
| D | `fold` を使った統合結果が、こちらの幾何統合と一致する(不一致率を報告します) |
| E | 既存の 2300 部品も新形式で再出力される(比較のため) |

**C が中心的な条件です。**現在の 7.8% が、拡張後にどこまで下がるかで抽出の網羅性を
判定します。

---

## 5. 互換性のお願い

- **既存のフィールドは消さないでください。**`cls`, `tau`, `refs`, `bin`, `nf`,
  `env_lo`, `env_hi` はそのまま
- 新フィールド(`loop`, `fold`, `side`, `angle`, `radius`)は**追加**の形で
- 新クラスが増えても、既存の `outer_boundary` / `bend_line` の意味は変えないで
  ください(現行モデルの再学習が必要になるため)

こちら側は、新フィールドが無い場合は現行動作にフォールバックする形で実装します。

# 回答: ワイヤーフレーム抽出の拡張

宛先: 生成モデル側
発信: PartMaker 側(合成部品の生成を担当)
Date: 2026-08-30

---

## 要旨

依頼を読み、**実測で検証しました。前提に2つ誤りがあります。**

1. **「穴の抽出漏れ」ではありません。部品に穴が存在しません。** 生成器は穴を一切作って
   いません。したがって 3.1(最優先)は抽出側の作業ではありません。**穴は追加しない
   方針が決まりました**(生成側の判断)。この前提でモデル側の設計を進めてください。

2. **曲率の情報は既に抽出されていて、そちら側の変換器が捨てています。**
   `cae_mesh_generator/wtok/convert.py` の 27 行目が `surface_frame` をスコープ外にし、
   199 行目が `crease` を `bend_line` に統合しています。ビード部品では
   **`surface_frame` が全辺の 36%(108本)**を占めます。受け入れ条件Cは、抽出を
   一切変えなくても、この破棄をやめるだけで大きく動く可能性があります。

そのうえで、**生成側から特徴のグラウンドトゥルースを出力しました**(2300部品ぶん、
出力済み)。B-Rep からの推定より正確です。詳細は §3。

---

## 1. 実測: 抽出器は既に6クラスを出している

抽出器 `fill_volume/wireframe_app/extract.py`(v4.4)のクラス:

```
outer_boundary / hole_boundary / bend_line / surface_frame / crease / seam
```

PartMaker の部品を実際に抽出した内訳:

| クラス | ビード部品 | フランジ部品 |
|---|---|---|
| bend_line | 150 | 28 |
| **surface_frame** | **108** | **21** |
| outer_boundary | 16 | 24 |
| seam | 26 | 9 |
| **hole_boundary** | **0** | **0** |

`surface_frame` は抽出器の定義で「曲面↔曲面の境界(フィレット骨格、曲面パネル間の
遷移)」です。**これがまさに「曲がっているのに bend_line から遠い表面」の正体**だと
考えられます。ビードの稜線フィレット・四隅の球面パッチ・フランジ根本フィレットの
内部構造線が全部ここに入ります。

`convert.py` のコメントは "fillet interiors are recovered from face assumptions A" と
書いていますが、**ビードにはこの仮定が成り立ちません**(単純なフランジ曲げと違い、
稜線Rが2本+四隅Rが独立に存在するため)。

### お願い

**抽出側を触る前に、`surface_frame` を通した場合の条件Cを測ってください。**
それで足りるなら、こちらの作業も含めて不要になります。

---

## 2. 穴について(3.1)

生成器は `hole_diameter_mm` を**サンプリングして joints.json に記録していますが、
ジオメトリには反映していません**。構築コードに穴を開ける処理が存在しないことを
確認済みです。600部品すべてでループが1本だったのは、抽出漏れではなく事実です。

抽出器も変換器も `hole_boundary` に対応済み(`SCOPE_CLASSES` に含まれる)なので、
**部品側に穴ができれば自動的に流れます**。

ただし今回、**穴は追加しない**判断になりました。複数ループへの一般化は、
このデータセットでは学習材料が得られません。

---

## 3. 提供するもの: 特徴のグラウンドトゥルース(実装済み)

`fold` / `angle` / `radius` / `side` は、B-Rep から推定するより**作った側が出すほうが
正確**です。生成器は各折れ目の角度・半径・傾き、ビード/フランジの全寸法、
余肉カットのRを厳密に知っています。

### 出力場所

```
synthetic_parts/<group>/features/<part_id>.json     # 2300部品ぶん出力済み
```

`params/` と同じ階層です。`mid/<part_id>_mid.stp` と1対1に対応します。

### スキーマ(`partmaker_features/1`)

```jsonc
{
  "part_id": "...", "half_width_mm": ..., "thickness_mm": ...,
  "panels": [{"origin":[x,y,z], "u":[...], "v":[...], "normal":[...],
              "near_run_mm":..., "far_run_mm":...}],
  "folds": [{
     "id": 0,                       // ← 依頼の `fold`
     "angle_deg": 83.5,             // ← 依頼の `angle`
     "radius_mm": 18.4,             // ← 依頼の `radius`
     "tilt_deg": -1.0,
     "sharp_line": [[x,y,z],[x,y,z]],        // フィレット前の理論折れ線
     "tangent_lines": [                       // ← 依頼の `side`
       {"side":0, "panel":0, "p0":[...], "p1":[...]},   // 円筒↔平面の接線(片側)
       {"side":1, "panel":1, "p0":[...], "p1":[...]}    // もう片側
     ],
     "concave_side": -1
  }],
  "bead": { /* 全寸法 + centreline + 稜線オフセット + run_out */ },
  "flange": { /* 全寸法 + root_curve + root_tangent_offset_mm */ },
  "corner_relief": [{"label":"p1/-v", "radius_mm":..., "arc":[[x,y,z],...]}],
  "has_inflection": false, "notes": []
}
```

**`tangent_lines` が 3.2 の「1つの折りが2本を生む」問題を確定にします。**
幾何推定での対統合(24本→15本、17.2%が対にならない)が不要になります。

### 検証済みの使い方

抽出された `bend_line` を、このサイドカーでラベル付けできることを実測しました
(`tools/qa_feature_label.py`、30部品 / bend_line 4263本):

```
bead        3409 (80.0%)     ← ビード由来
bend_line    854 (20.0%)     ← 基準面の折れ目(fold id と side が確定)
UNEXPLAINED    0 ( 0.0%)
説明できた全長比: 100.0%
```

**ラベル付けの方法**(これが重要です):

- **折れ目**は「線」なので `tangent_lines` との距離で厳密照合(許容2mm)
- **ビード/フランジ**は曲線の厳密照合をしないでください。稜線は
  **フットプリント全周の閉ループ**(端キャップ・四隅R・曲げフィレット横断を含む)で、
  再現は割に合いません。**中心線からの距離による領域判定**を使ってください:

  ```
  ビード由来 ⇔ dist(edge, bead.centreline) ≤ half_footprint_mm + ridge_setback_mm + 2
  フランジ由来 ⇔ dist(edge, flange.root_curve) ≤ root_radius_mm + height_mm + 2
  ```

  曲線照合では 71.8% が未説明でしたが、領域判定にすると 0% になりました。

### 注意点(正直に)

- **頂稜線の持ち上がり向き(±法線)は params に残っていません。** 構築時にCATIA側の
  プローブで決まるためです。`top_ridge_lift_mm` を出しているので、両符号を候補にして
  近いほうを採ってください。必要なら生成器に記録を追加します。
- `bead.centreline` / `flange.root_curve` は**平坦区間のみ**の標本です(曲げフィレット上は
  採っていません)。領域判定には十分ですが、曲線として使うなら間が空きます。
- `corner_relief` の円弧は**外形側**の特徴です(依頼の表では曲げクラスに分類されて
  いましたが、実体は外周の余肉カットで、`outer_boundary` に現れます)。

---

## 4. 3.3(短いセグメント)への回答

**破片ではありません。意味のある短い曲げです。**

ビード部品は **125面という極めて規則的なトポロジー**を持ちます(2300部品中1725部品が
面数125ちょうど、p10=p90=125)。この面数を作っているのは:

- ビードの足元R・頂稜線R(全周の閉ループ、曲げフィレットを横断して分割される)
- 四隅R(球面パッチが生じる)
- 基準面の曲げフィレット2本

`bend_line` の61%が10mm未満なのは、**これらが曲げフィレットや四隅で細かく分割される
から**です。切り捨てると、ビードの稜線が虫食いになります。

§3のラベル付けを使えば、短いセグメントも `bead` として正しく分類できるので、
長さで切る必要はありません。

---

## 5. `inflection` について

**このデータセットには存在しません。** 基準面は「平面 + 円筒フィレット」の区分構成で、
平坦部の曲率は厳密に0、フィレット内では曲率一定です。「曲率の符号が変わる線」は
生じません。

折れ目の凹凸が反転するS字部品は存在します(`has_inflection: true` で出しています)が、
反転は2つの折れ目の**間の平坦パネル全体**で起きるので、線にはなりません。

---

## 6. 3.4(締結点以外の拘束点)

現状、部品には締結点2点しかありません(構造上そうなっています)。位置決めピンや
溶接点を足すには**生成器の設計変更**が必要で、形状生成そのものに影響します。
優先度が上がったら相談してください。

なお §3 のサイドカーは、締結点から導出できない情報(実際に構築された折れ目の
角度・半径・傾き、ビード/フランジの寸法)を含みます。**3.4 の狙い(締結点から
導出できない新しい入力)に部分的に応えるものです** — ただしこれは「入力」ではなく
「教師信号」として使うほうが自然だと思います。

---

## 7. 受け入れ条件への対応状況

| # | 条件 | 状況 |
|---|---|---|
| A | `loop` で境界復元 | **対象外**(穴が無いのでループは常に1本。`outer_boundary` のみ) |
| B | 穴のある部品で `inner_boundary` | **対象外**(穴を作らない方針) |
| C | 曲がっているのに曲げ線から遠い表面が減る | **まず `surface_frame` の破棄をやめて測ってください**。加えて §3 のラベル付けで bend_line の100%が説明できます |
| D | `fold` 統合が幾何統合と一致 | **`tangent_lines` で確定できます**(推定不要)。不一致率を報告してください |
| E | 既存2300部品も新形式で | **サイドカーは2300部品すべて出力済み**。STP自体は不変です |

---

## 8. 互換性

§5のお願いは守っています。**STPは一切変えていません。**サイドカーは
`features/` に**追加**しただけで、既存の `mid/*.stp`、`params/*.json`、
`annotations/joints.json` は不変です。新フィールドを読まない実装はそのまま動きます。

---

## 9. 次に何をするか

こちらから提案する順序:

1. **そちら側で `surface_frame` を通して条件Cを測る**(抽出側の変更ゼロ)
2. §3のサイドカーで `bend_line` にラベルを付ける(`fold`/`side`/`bead` が確定)
3. それでも足りない曲率が残ったら、そのとき抽出器の拡張を検討する

1と2で足りる可能性が高いと見ています。測った結果を教えてください。

```
<chunk>/variants/<part_id>__<knob>=<value>_mid.stp   形状(ゲートは本体と同一: 直線/円弧のみ、
                                                     外形ループ 1、二面角 ≤150°、締結点が面上)
<chunk>/variants/params/<name>.json                 spec + bead/flange/rib + knob/value/changed
<chunk>/variants/features/<name>.json               faces[](features v2 と同じ面ラベル)
<chunk>/variants/<name>.infeasible                  不成立の理由
<chunk>/variants/manifest.json                      {"parts": {part_id: [{name, knob, value,
                                                     changed:{field:[before,after]}, status, file|reason}]}}
```

- `annotated_points` / joints は元部品と同一(params の spec に同じ値が入っている)。
- 既存の `mid/ params/ features/ annotations/` は触っていない。
- 暫定ツールが置いた `__side±1_mid.stp`(occt11/13/15/16、各 600)は残してある。新しい
  `__side=±1` と同じ設計なので、どちらかを消してよい(こちらは消していない)。
- 再実行は済んだ名前を飛ばす。部品ごとの乱数は part_id から決まる(再現可能)。
- フランジのキラリティ再試行(本体の `build_general_part` が根本フィレット失敗時に側×方向を
  反転する救済)は**使っていない**。knob を勝手に変えないため。

## 3. 出力の契約(依頼 B)

```
<chunk>/perturb/<part_id>__p<k>_<dx>_<dy>_mid.stp
<chunk>/perturb/<part_id>__p<k>_<dx>_<dy>.json
    {source_part_id, kind, point_index, moved_from, moved_to, vector_xyz,
     distance_over_bearing, joints[], faces: {changed, unchanged, added, removed}, face_labels[]}
<chunk>/perturb/manifest.json
```

### 3.1 摂動の取り方

- 点は point1/point2 から等確率で 1 つ。法線は保ち、**面内**(法線に直交する乱数方向)に
  座面半径の 0.5〜2.0 倍だけ動かす。
- 他の設計選択(slack、帯幅、ビード/フランジ/リブのパラメータ)は元のまま。
- 成立しなければ引き直し(1 摂動あたり最大 6 回)。不成立は manifest に理由つきで残す。

### 3.2 面の差分

features v2 の `faces[].name` で対応づけ、面積が 1% 以上または重心が 0.5mm 以上動いた面を
`changed`、名前が増えた/消えたものを `added`/`removed`。掃引族では締結点を動かすと中心線が
変わるので、多くの面が `changed` になる(端パネルの座面まわりが最も大きく動く)。

### 3.3 未対応: 011 型 / 014 型

occt15/16 は掃引のアンカー(point1/point2)が実点ではなく、対の中点などの**仮想点**で、
実点は `annotated_points` として面上判定だけに使っている。実点を 1 つ動かしても
面は変わらず(X' = X)、動かした点が帯から外れれば不成立になるだけで、教師にならない。
対応するには「動かした実点からアンカーを再導出する」(族の対配置ロジックの逆問題)が要る。
必要なら次の依頼で。「1 点追加」も同じ理由で未着手。

### 4.2 依頼 B(2 点族 + 007 型、各 100 部品 × 3)

| チャンク | ペア | 引き直しで不成立 | 変化した面の数(中央値) |
|---|---|---|---|
| occt11 | 298 | 254 | 39 |
| occt12 | 300 | 48 | 12 |
| occt13 | 300 | 37 | 7 |

- occt11 の不成立が多いのは 2 曲げ部品で、点を動かすと slack 固定のままでは折りが
