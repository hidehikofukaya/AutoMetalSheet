## 1. 条件C — 密度を揃えて測り直した結果

全ての辺集合を **1mm 間隔に再サンプルしてから**距離を取りました(60部品)。

| 辺の集合 | 曲がっているのに15mm以上離れた表面 | p90 |
|---|---|---|
| 抽出元の `bend_line`(生ポリライン) | **0.0%** | 1.2% |
| 変換後の `bend_line` | **0.0%** | 1.2% |
| 私の `fold_lines`(10mm切り + 対統合) | **0.0%** | 1.3% |
| 抽出元 `bend_line` + `surface_frame` | **0.0%** | **0.0%** |

**変換器は何も失っていません**(抽出元と同一)。**私の10mm切りと対統合もほぼ何も
失っていません**(p90 で 1.2% → 1.3%)。

### なぜ 7.8% が出たか

`realize_edge` は LINE を **2点**で実現します。長い直線の中間には点が存在しないので、
その近くのサーフェス点が「どの曲げ線からも遠い」と判定されていました。

密度を揃えなかったことが原因で、**同種の誤りは今回で4回目**です。こちらの評価手順に
「距離を取る前に必ず両側を同じ間隔に再サンプルする」を常設ルールとして入れました。

### 変換器の実測(120部品)

| | 辺の数 | 総延長 |
|---|---|---|
| 抽出元 `bend_line` | 13,595 | 128,117mm |
| 変換後 `bend_line` | 6,851 | **128,072mm(100%)** |

辺の数が半減しているのは**隣接ポリラインを1つのプリミティブに連結している**ためで、
長さは保持されています。落としていません。

## 2. `surface_frame` について

ご指摘は事実でした。`convert.py`:

```python
SCOPE_CLASSES = {"outer_boundary", "hole_boundary", "bend_line", "crease", "feature_rim"}
#                                    surface_frame と seam が無い
cls = "bend_line" if cls in ("crease", "feature_rim") else cls
```

抽出元での規模も確認しました(120部品):

| クラス | 辺の数 | 総延長 | |
|---|---|---|---|
| `bend_line` | 13,595 | 128,117mm | 使用 |
| **`surface_frame`** | **11,894** | **72,307mm** | **破棄** |
| `outer_boundary` | 2,153 | 64,643mm | 使用 |
| `seam` | 1,856 | 9,359mm | 破棄 |

**抽出された全長の 30% を捨てていました。**

条件Cへの効果は裾だけですが、**面(第3段)の生成には効く可能性が高い**ので
`SCOPE_CLASSES` に `surface_frame` を追加します。`seam` は保留(意味を把握して
いないため。何を表すか教えてください)。

**ただし `bend_line` への統合はしません。**別クラスとして流し、生成側で別スロットに
します。曲げ線とフィレット骨格は板金設計上の意味が違うためです。

## 3. 短いセグメント(3.3)

「破片ではない、ビードの稜線」という回答、了解しました。ただし測定上は、10mm で
切っても条件Cは p90 で 1.2% → 1.3% しか動きません。

**それでも切るのをやめる方向で検討します。**理由は条件Cではなく、そちらのご指摘
どおり**ビードの稜線が虫食いになる**ことのほうが、ワイヤーフレームの成果物として
問題だからです。現在の曲げ表現は24スロットで、10mm切りをやめると本数が
大幅に増えるので、表現側の再設計が要ります。ビードのラベルが付けば
**「ビード由来はまとめて1つの閉じた特徴」**として扱えるので、§4 と合わせて対応します。
