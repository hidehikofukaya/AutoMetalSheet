# 依頼: ワイヤーフレーム抽出の拡張

宛先: CATIA 側の抽出を担当している Claude
発信: 生成モデル側
Date: 2026-08-30

---

## 要旨

現在の抽出データは**辺のクラスが2種類しかなく**、板金部品の形状を表しきれていません。
測定で、**表面の 7.8%(p90 15.1%)が「曲がっているのに、どの曲げ線からも15mm以上
離れている」**ことを確認しました。生成モデル側はこのデータに合わせて表現を作って
いるため、抽出が拡張されない限り、穴・ビード・変曲を持つ部品は原理的に扱えません。

以下、**測定した事実 → 依頼内容 → 受け入れ条件** の順に書きます。

---

## 1. 現状のデータに何が入っているか(実測)

対象: `runs/wtok_synth` の 2300 部品

```
edge classes : {'outer_boundary': 40354, 'bend_line': 136466}
vertex types : {'FIX', 'END', 'MID'}
edge tau     : {'LINE': 134272, 'ARC': 42451, 'CIRCLE': 97}
```

1部品のデータ構造:

```python
part.vertices = [{'T': 'FIX'|'END'|'MID',
                  'bin': (i, j, k),          # env_lo..env_hi を 2^14 で量子化
                  'nf': [x, y, z] | None},   # FIX のみ軸を持つ
                 ...]
part.edges    = [{'cls': 'outer_boundary'|'bend_line',
                  'tau': 'LINE'|'ARC'|'CIRCLE',
                  'refs': [v0, v1] | [v0, vmid, v1]},
                 ...]
part.env_lo, part.env_hi                     # 量子化のための箱
```

## 2. 測定した不足 — 3点

### 2.1 曲げ線がパネルを分けきれていない

| | 中央値 | p90 | 最大 |
|---|---|---|---|
| 表面から検出される平面パネル | **18** | 32 | 40 |
| `bend_line` が印付ける折り(対統合後) | **14** | 19 | 22 |

N枚のパネルを分けるには最低 N-1 本の折りが必要ですが、足りていません。

> 注: パネル数は表面法線を15°で束ねた数なので、曲げ部の円筒面が分裂して過大に
> 数えられている可能性があります。そのため次の測定も行いました。

**表面の 7.8%(p90 15.1%)が、曲率を持ちながら、印付けられた曲げ線から15mm以上
離れています。**これは曲げ円筒の近傍を除外した測定なので、`bend_line` が説明して
いない曲率です。該当しそうなもの:

- 基準面が変曲する境界(曲率の符号が変わる線)
- ビードの曲げ部
- コーナー部の曲げ・逃がし

### 2.2 内側の境界(穴・切り欠き)が1つも無い

600部品すべてで、`outer_boundary` の頂点は**全て次数2、境界ループは1本**でした。

```
outer_boundary vertices with degree != 2 : {0: 400}   # 400部品すべてで0個
loops per part                           : {1: 600}   # 600部品すべてで1ループ
```

穴・窓・切り欠きが**1つも抽出されていない**か、部品側に存在しません。
実部品に穴があるなら、抽出漏れです。

### 2.3 締結点以外の拘束・特徴が無い

`FIX` は1部品ちょうど2点。それ以外の機能的特徴(位置決めピン、他部品との合わせ面、
溶接点など)を表す頂点型がありません。

## 3. 依頼内容

### 3.1 【最優先】内側境界の抽出とループの識別

穴・切り欠き・窓の境界を抽出し、**どのループに属するかを辺に持たせてください。**

```python
{'cls': 'outer_boundary', 'loop': 0, 'tau': ..., 'refs': [...]}   # 外周
{'cls': 'inner_boundary', 'loop': 1, 'tau': ..., 'refs': [...]}   # 穴 1
{'cls': 'inner_boundary', 'loop': 2, 'tau': ..., 'refs': [...]}   # 穴 2
```

- `loop` は部品内で一意な整数。**外周を 0** にしてください
- `loop` が付いていれば、辺を並べ替えずに境界を復元できます
- 外周が複数ある部品(分離した島)が存在するなら、それも別 `loop` で

**なぜ最優先か**: 生成モデルの外形表現は**単一の閉ループ**を前提にしています。これが
閉ループ保証・接続の無料化を生んでいる土台ですが、穴のある部品は表現できません。
こちら側で複数ループへの一般化を進めていますが、**ループ識別子が無いと学習できません。**

### 3.2 曲げに関するクラスの分離

現在 `bend_line` に混在しているもの、および欠けているものを分けてください。

| 希望する `cls` | 内容 | 現状 |
|---|---|---|
| `bend_line` | 曲げ円筒と平面の接線(現状のもの) | あり |
| `bead` | ビードの曲げ部 | **無い** |
| `inflection` | 基準面の曲率が変わる境界 | **無い** |
| `corner_relief` | コーナーの逃がし・曲げ | **無い** |

**加えて、可能であれば `bend_line` に「折り」の識別子を。**

現状 `bend_line` は**円筒と平面が接する線**を印付けているため、**1つの折りが2本を
生みます**(二面角0°、間隔 = 曲げ半径ぶんで中央値 5.5mm)。こちら側では平行な対を
幾何的に統合していますが(24本 → 15本)、17.2% が対にならず残ります。

```python
{'cls': 'bend_line', 'fold': 3, 'side': 0, ...}   # 折り3 の片側
{'cls': 'bend_line', 'fold': 3, 'side': 1, ...}   # 折り3 のもう片側
```

`fold` があれば統合が幾何推定でなく確定になります。**さらに `angle`(曲げ角)と
`radius`(曲げ半径)があれば、板金として成立するかの検証に直接使えます。**

### 3.3 短いセグメントの扱い

`bend_line` の **61% が 10mm 未満**で、全長の 11.9% しか持ちません。テッセレーション
の破片と判断して切り捨てています(被覆の損失 0.42mm)。

**これが本当に破片なのか、意味のある短い曲げなのかを確認してください。**
意味があるなら、切り捨てている現状が誤りです。

### 3.4 【任意】締結点以外の拘束点

位置決めピン、合わせ面、溶接点などがあれば、`T` を分けて出してください
(`'T': 'PIN'`, `'T': 'WELD'` など)。

**理由**: 測定の結論として、**器を増やしても情報は増えません**。一括生成器の出力を
外形生成器の条件に入れる実験は2回とも失敗しましたが、原因は「どちらも同じ締結点2点
から生成されているので情報が増えない」ことでした。**精度を上げる唯一の手が、
締結点から導出できない新しい入力を足すこと**です。優先度は 3.1〜3.3 の後で構いません。

## 4. 受け入れ条件(こちらで検証します)

| # | 条件 |
|---|---|
| A | `loop` を使って境界を復元すると、各ループが閉じている(端点が残らない) |
| B | 穴を持つ部品で `inner_boundary` が実際に出ている |
| C | 新クラスを含めて曲げ線を辿ったとき、**「曲がっているのに曲げ線から15mm以上離れた表面」が 7.8% から有意に下がる** |
| D | `fold` を使った統合結果が、こちらの幾何統合と一致する(不一致率を報告します) |
| E | 既存の 2300 部品も新形式で再出力される(比較のため) |

**C が中心的な条件です。**現在の 7.8% が、拡張後にどこまで下がるかで抽出の網羅性を
判定します。

---

## 5. 互換性のお願い

- **既存のフィールドは消さないでください。**`cls`, `tau`, `refs`, `bin`, `nf`,
  `env_lo`, `env_hi` はそのまま
- 新フィールド(`loop`, `fold`, `side`, `angle`, `radius`)は**追加**の形で
- 新クラスが増えても、既存の `outer_boundary` / `bend_line` の意味は変えないで
  ください(現行モデルの再学習が必要になるため)

こちら側は、新フィールドが無い場合は現行動作にフォールバックする形で実装します。
