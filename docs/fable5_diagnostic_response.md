## 0. エグゼクティブサマリ

レポートの数値はすべてローカル成果物と一致しており、「データ多様性が律速」という方向性の診断は正しい。ただしローカル検証で、レポートに書かれていない **2つの構造的問題** を発見した。どちらも今後の実験判定を歪めるため、軸アブレーションより先に対処すべきである。

1. **評価系がサンプリング解像度の床に律速されている。** 512点評価では、モデルが完璧でも bbox対角の約2.7%(250mm級パーツで約7mm)の Chamfer が出る。train Chamfer 11.0mm は床の約1.7倍 = ほぼ記憶完了、val 23.0mm = 床の約3.5倍が本物の汎化ギャップ。近年の実験間の±2mm差はこの床とval 6パーツのノイズに埋もれて判別不能だった可能性が高い。

2. **学習サンプリングが全epochで凍結されている。** `fill_volume_dataset.py:154` の `stable_record_seed(self.seed, part_id|variant)` により、各パーツは300epoch通して**完全に同一の512点**しか提示されない。epoch毎の再サンプリングという事実上無料の増強が未使用のまま残っている。mirror-y が効いた理由の一部は「モデルが見たことのない唯一の新規サンプルだったから」である可能性がある。

## 1. ローカル検証の結果

### 1.1 レポート数値の照合

- `runs/cae_mesh_structured_q20_60_n24_mirror_y_seed13_eval_all24_best/aggregate_metrics.json` の val 集計(Chamfer 23.010 / recon p95 29.189 / target p95 19.851 / target within 5mm 0.194 / boundary p95 21.778 / worst `081` 28.594)はレポート §6.8 と完全一致。
- `history.json`(300 epoch)で train loss は 0.72 → 0.094 まで単調減少に近く、終盤も微減継続。過学習傾向の記述と整合。

### 1.2 サンプリング床の実測(新規)

方法: `preview_target.ply`(512点)をランダムに半分ずつに分割し、相互最近傍距離を計算。

- 256点 vs 256点 の自己Chamfer = 正規化bbox対角の **3.88%**
- 512点換算(×1/√2)≈ **対角の2.7%** → 250mm級パーツで **約6.8mm**

これが「同一表面の2つの独立サンプリング間ですら出る誤差」= 評価の床である。

帰結(パーツ別 `metrics.json` で確認済み):

| 指標 | train | val | 解釈 |
|---|---:|---:|---|
| Chamfer mean mm | 11.0 | 23.0 | train は床の~1.7倍(ほぼ記憶完了)、val は~3.5倍 |
| target within 2mm | 0.06 | ~0.01 | **train ですらほぼゼロ** = 512点では物理的に測定不能 |
| target within 1mm | 0.01 | ~0.00 | 同上 |

CAE メッシュの mm 精度目標は、現在の評価解像度では**そもそも測れない**。「点群AEが表現の天井に近い」(§7.1-5)は、表現の天井の前に**測定の天井**に当たっている、と読み替えるべき。

### 1.3 サンプリング凍結の確認(新規)

`fill_volume_dataset.py`:

- L154: `sample_seed = stable_record_seed(self.seed, f"{record.canonical_part_id}|{variant}")` — seed はパーツ+variant に対して決定的
- L164-165: surface / boundary サンプリングは毎回この固定 seed を使用

→ 18パーツ × 512点 = **9,216個の固定座標** が学習データの全て。train Chamfer が床に張り付くのは当然で、これは「データ多様性不足」の少なくとも半分が**同一パーツ内の点多様性不足**であることを示唆する。

正規化(L155-156)は bbox 中心 + 最大辺による等方スケーリングで、thin strip を歪めない。この点は問題なし。

## 2. §9 の質問への回答

**Q1. mirror-y はデータ多様性か座標バイアス隠しか?**
単一軸の結果からは判別不能。§8.1 の軸アブレーションが正しい判別実験である。判定基準: x/z も同程度に効く → サンプル倍増+座標正則化効果。y だけ効く → 左右対称ファミリの実在。ただし §1.3 の通り、**epoch毎再サンプリング導入後に mirror の効果を再測定すべき**。点多様性が供給されると mirror の寄与が変わる(交互作用がある)可能性が高い。

**Q2. train-only mirror は妥当か? 必要なチェックは?**
妥当。板金には実車で左右勝手違い部品が普通に存在し、ミラーした中立面は製造可能な形状なので、どの軸でも「非物理」にはなりにくい。懸念されているより頑健である。チェックは3点で、うち2点は実施済み: ①法線の反転整合(済)、②分割後ミラーによるリーク防止(済)、③将来、向き依存特徴(joint の側の符号等)を追加する場合の反転整合。

**Q3. 次はアンカリング / グラフ / データ増強のどれか?**
順序: **測定の較正 → 点多様性(再サンプリング)→ 軸アブレーション → アンカリング → グラフ**。ただしアンカリングには**学習ゼロの事前診断**がある: 既存チェックポイントで val パーツのスキャフォールド出力点の対ターゲット距離を train パーツと比較するだけ。val で大きく外れていれば仮説確定、外れていなければ実装不要と実装前に分かる。tangent-frame の失敗パターン(誤ったスキャフォールドを局所的に一貫して間違える)はこの仮説を支持するが、測ってから作るべき。

**Q4. メトリクスは十分か?**
2つ不足。①**床で正規化した指標**: Chamfer を「同一パーツ2サンプリング自己Chamferの何倍か」または「bbox対角比%」で併記。これがないとパーツサイズと誤差が交絡する(worst target p95 の `1285:10` は大型パーツであることの寄与が分離できない)。②**評価時のみ target を高解像度化**(例: target 4096点 vs recon 512点)。target-to-recon 側の解像度が上がり、within 1/2mm が初めて意味を持つ。学習側の変更は不要。

**Q5. checkpoint 選択で boundary を重くすべきか?**
否。boundary within 5mm は val 6パーツ × 128点で最もノイジーな指標であり、これに選択を最適化すると分割ノイズへの過適合になる。`best_by_val_boundary_*` の保存(実施済み)で十分。選択は Chamfer/target 系、boundary は報告のみ。

**Q6. 分割戦略は?**
24パーツ・1seed の単一 18/6 分割では結論が出ない。推奨: **slenderness(細長さ)で層化した 4-fold 交差検証**。`081` が孤立外れ値か thin-strip ファミリの系統的失敗かはこれで初めて判別できる。アセンブリホールドアウトは真の汎化テストだが 2 アセンブリでは厳しすぎるため、最適化対象にせず参考値として1回測るに留める。

**Q7. AE 継続か Mesh IR 移行か?**
較正した測定で **AE をもう1フェーズ**。AE はまだ本来の診断課題(スキャフォールド配置は汎化するか)に答えておらず、未解決のままより難しい出力空間に移ると失敗時の切り分けができない。Mesh IR は**データ構造設計のみ**並行で進める(学習不要でリスクゼロ)。

**Q8. アンカリング検証の最小実験は?**
Q3 の学習ゼロ診断が最小(評価スクリプト1本)。陽性なら §8.4 の最小版: 自由学習クエリ → FPS中心アンカー+残差オフセット、**他は全て同一**で1ラン。比較指標は scaffold Chamfer(ログ済み)と val recon p95(偽陽性シート量)。

## 3. fable5 独自の改善提案(優先度順)

### P0-a. 評価の較正(コード変更最小・効果最大)

- 評価時 target サンプル数を 4096 に(recon は 512 のまま)
- 各パーツの自己Chamfer床を計測して `metrics.json` に併記
- Chamfer/対角比(%)のスケール正規化指標を追加

これを先にやらないと、以降のどの実験も差が測れない。

### P0-b. epoch毎の点再サンプリング(train のみ)

`sample_seed` に epoch またはグローバルステップを混ぜるだけの小変更。効果予測:

- 18パーツ×512点の固定 9,216 点 → 実質無限の点バリエーション
- train の床張り付き(=記憶)を直接妨害し、汎化ギャップ 11→23mm の縮小が期待できる
- **注意**: val は固定 seed のまま維持(過去実験との比較可能性のため)
- **注意**: 導入後に mirror-y を再アブレーションすること。mirror の効果の一部が「唯一の新規サンプルだったから」なら、再サンプリング下では縮む

データ増強の議論(§8.1, §8.2)の前に、この「タダで手に入る多様性」を回収すべき。

### P1-a. スキャフォールド配置の学習ゼロ診断

既存 `best.pt` で val/train のスキャフォールド出力点→ターゲット距離分布を比較する評価スクリプト。§8.4 実装の go/no-go を1日で判定できる。

### P1-b. 軸アブレーション(codex 計画通り、ただし較正済み指標で判定)

no / x / y / z の4条件。P0 の指標で判定し、±1σ(自己Chamfer床由来のノイズ)以内の差は「同等」と扱う。

### P2-a. スケール条件付け

現在の正規化は絶対スケールを完全に破棄しているが、板金の特徴寸法(曲げR、フランジ幅、穴径)は**絶対mm**で決まる。`scale` は既に dataset が返している(L237)ので、`log(scale_mm)` を1トークンとしてエンコーダに供給するだけ。normalized 空間で「このパーツの 0.01 は実寸何mmか」をモデルが知れるようになる。

### P2-b. EMA(重み指数移動平均)または checkpoint 平均

小データで終盤過学習が既知(§6.1, §6.8)の状況では、EMA は実装コスト極小で val を安定化させる定番。early stopping への依存も減る。

### P2-c. slenderness 層化 4-fold(Q6 の実行)

### P3. スキャフォールドアンカリング(P1-a が陽性の場合のみ)/ Mesh IR 設計並行

### やらないことの推奨

- **エンコーダ/フュージョンへの attention 追加投資は凍結**。lattice・tangent の2連続陰性は codex の結論通りで、測定較正後もこの優先度は変わらないと予測する。
- boundary 指標への checkpoint 選択最適化(Q5 の通りノイズ過適合)。

## 4. 修正版実行順(§10 の置き換え)

1. 評価較正(P0-a)— 既存チェックポイントの再評価も含む。過去の全比較表を較正済み指標で作り直す
2. epoch毎再サンプリング(P0-b)で1ラン
3. スキャフォールド配置診断(P1-a)— 1・2 と並行可能
4. 軸アブレーション(P1-b)— 再サンプリング込み構成で
5. 最良構成を層化 4-fold で確認(P2-c)、EMA 追加(P2-b)
6. P1-a 陽性ならアンカリング実装、Mesh IR はデータ構造設計のみ並行

## 5. 一文要約

「データ多様性が律速」という codex の診断は方向として正しいが、その手前に (a) 512点評価による約7mmの測定床と (b) 全epoch同一512点という学習サンプリング凍結の2つの構造的問題があり、これらを直すこと(評価較正+epoch毎再サンプリング)が、軸アブレーションを含む今後の全実験の判定精度を決める最初の一手である。
