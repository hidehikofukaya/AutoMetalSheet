# 11. 汎用性の監査 — 特定形状への特化を洗い出す

Date: 2026-08-30
方針(ユーザー指示): **特定形状に特化した設計は今後一切許容しない。**
どんな構造・どんな締結点の板金でも学習・生成できること。

---

## 11.1 判定の基準

| 分類 | 意味 | 対処 |
|---|---|---|
| **構造的** | コードが表現しようがない。数字を変えても直らない | 再設計 |
| **上限** | 固定枠。余裕があるかは実測で分かる | 枠を広げる/可変化 |
| **経験定数** | このデータに当てはめた閾値 | データ由来に置換 |

---

## 11.2 構造的な問題(再設計が要る)

### S1. 締結点フレームは**ちょうど2点**を前提にしている ★最重要

```python
d  = |P[1] - P[0]|          # 尺度 = 2点間距離
e1 = (P[1] - P[0]) / d      # 第1軸 = 2点を結ぶ方向
origin = midpoint(P[0], P[1])
```

実測:

| 締結点数 | 挙動 |
|---|---|
| 1 | `unit = 1.000`、回転 = 単位行列。**向きも尺度も決まらない** |
| 2 | 正常 |
| 3 | `unit` は2点のまま。**3点目はフレームに寄与しない** |
| 4以上 | `COND_ROWS = 4` なので**条件行にすら入らない**(最大3点) |

データは **400/400 部品が2点ちょうど**。つまりこの設計は、データが2点しか
持たないことに完全に依存している。**システム全体で最も深い特化。**

座標系が壊れると、正規化座標・ガード円板・条件付け・評価の全部が同時に壊れる。

### S2. 折りの本数が `[:2]` でハードコード

```python
for f in (x.get("folds") or [])[:2]:
```

データの最大値は 2。**余裕ゼロで、データの形をそのまま書いている。**
ビードとフランジも「各1個まで」。

### S3. 種別 one-hot とパラメータの種別依存デコード

`KINDS = ("fold", "bead", "flange")` は PartMaker 生成器の語彙。
パラメータ5チャネルの**意味が種別ごとに変わる**。

実測(サイドカーの厳密パラメータから断面を構成、900本):

| | 値 |
|---|---|
| 主成分2つで説明される多様性 | **98.0%** |
| 最近傍平均で種別を復元 | **73%** |

**3つの種別は既に分離できていない。**連続体に乗っている。リブ・ルーバー・
エンボスが入れば区別は完全に消える。

### S4. 外形は単一の閉ループ前提(採用中のもの)

複数ループ版(`MULTI_CH`)は実装・検証済みだが休眠。穴を作らない方針のため。
**表現能力は既にあるので、これは構造的問題として残っていない。**

## 11.4 経験定数(データ由来に置換すべき)

| 定数 | 値 | 問題 |
|---|---|---|
| `BEND_MIN_MM` | 10.0 | **PartMaker 側から「破片ではない」と否定済み。**ビード稜線を虫食いにする |
| `BEND_MERGE_DEG/MM` | 8°/25mm | 幾何的な対統合。サイドカーの `fold`/`side` で確定に置換可能。現状17.2%が対にならない |
| `K_MAX` / `DK_MAX` | 0.2 / 0.05 | 「板金に鋭い角は無い」という前提。1%を割り切る設計 |
| `NRM_WIN` / `NRM_TOL` | 1 / 0.06 | 平面法線の窓。18辺の外形に合わせて選んだ |
| `LOWPASS_KEEP` | 25 | 外形のフーリエ帯域 |
| `ANCHOR_R` | 10mm | ガード円板。15mmでは傾き49°になる実測に基づく |
| `CONSIST_LAMBDA` | 2.0 | 3回の抽出で選定 |

## 11.5 断面ベースは汎用か — 慎重な検討

断面表現が**暗黙に仮定していること**:

| # | 仮定 | 破れる場合 |
|---|---|---|
| a | 特徴には**スパイン曲線**がある | **ディンプル・球状エンボス**にはスパインが無い |
| b | 断面はスパインに沿って**ほぼ一定** | **ラン・アウト**(ビード端の先細り)、テーパーリブ |
| c | 断面は横断方向1変数の**連続関数** | **ルーバー**(板が切れている) |
| d | 特徴どうしが**交差しない** | リブが折りを横切ると交差部の断面が未定義 |

**つまり断面ベースは「分類より汎用」だが、まだ「スパインに沿った押し出し」への
特化である。**種別one-hotより一段良いだけで、汎用ではない。

### 汎用に近づける修正

| 仮定 | 修正 | コスト |
|---|---|---|
| b | **断面をスパインの各ステーションで持つ**(一定ではなく変化する) | 断面 × ステーション数 |
| a, c | **閉じたスパインを許す**(`closed` フラグ)。ディンプルは長さ0の閉スパイン | 1ch |
| — | 端点の接続先を型として持つ:**外形上 / 他の特徴上 / 閉じているので端が無い** | 2ch |

**端が宙に浮かない保証は、この3値で維持できる** —
「閉じている」か「両端が何かに接続している」かのどちらかしか表現できない。

一般形:

```
特徴スロット:
  unused                     1
  closed                     1     ← 閉スパイン(端が存在しない)
  アンカーA: 型 + 位置        3     ← 外形上 / 他の特徴上
  アンカーB: 型 + 位置        3
  スパイン制御点              3*Nc
  断面 × ステーション         2*Ks*(Nc+2)   ← 変化する断面
```

**種別・折り本数・ビード個数のいずれも現れない。**新しい特徴型は「別の断面形状」
であって新クラスではない。

## 11.6 まだ検証できないこと

| 一般化 | 検証できるか |
|---|---|
| 締結点 1個 / 3個以上 | **データが全部2個。検証不能** |
| 折り3本以上 | **データが全部2本。検証不能** |
| ビード2個以上 | データに無い |
| ラン・アウト | `run_out` が全部品で 1.00 の定数。**変化が無く検証不能** |
| ディンプル・ルーバー・リブ | データに無い |
| 穴 | 作らない方針 |

**構造だけ用意し、埋まっていないチャネルは今日のデータで恒等に潰れる形にする**のが
唯一取れる方針。「実装したが検証されていない」ことを明示して残す。

## 11.7 締結点1個の問題は情報の問題である

締結点が1個のとき、**部品の寸法は入力から決まらない**。これはコードの欠陥ではなく
課題の性質。2点なら間隔が尺度を与えるが、1点にはそれが無い。

したがって選択肢は2つ:

| 案 | 内容 | 帰結 |
|---|---|---|
| A | 常に**絶対座標(mm)**で生成する | 締結点数に依存しない。ただし2点の場合に現在得ている尺度の正規化を失う |
| B | 締結点数で正規化を切り替える | 汎用に見えて、実は場合分けという特化 |

**Aが方針に合う。**ただし現在の性能(中央選択5.47mm)が正規化に依存している可能性が
あり、切り替えの効果は測る必要がある。**これはユーザーの判断を仰ぐべき設計分岐。**
